## 1. 世界观与主题

### 1.1 「梁」的梗
段位体系以「梁」为家族命名（小难梁 → 梁祖），这是产品的记忆点：
- 谐音/梗来源：DeepSeek 创始人梁文锋的姓氏「梁」（梁子/梁圣/梁神/梁祖 均为由此衍生的玩家尊称梗）。
- 氛围：跟 DSH 的产品气质一致（清晰、克制、技术感，但允许有趣）。

### 1.2 叙事（一句话）
「DSH 忙它的，咱们打我们的。赢了算你的，输了……再领 200k 继续。」

### 1.3 视觉基调
- 白色内容面与浅灰牌桌，蓝色主操作色 + 红/金语义强调色，贴近 DSH 的轻量工作台界面。
- 布局：无独立顶部信息栏，直接进入中央低对比度牌桌画布；顶部揭示底牌，左右两侧放对手，中间展示上一轮出牌，底部是自己的手牌，操作按钮位于手牌上方。
- 底牌在叫地主阶段保持隐藏，确认地主并进入出牌阶段后再揭示；地主身份标记与底牌保持同一时机出现。
- 大厅将玩家信息与 Token 余额纵向排列在同一信息组内；右下角斗地主入口复用主按钮的蓝色、圆角与字号规范。
- 组件：桌别和操作使用胶囊化按钮；对手展示头像、昵称和手牌数量，不用厚重面板或成排牌背填充空间。
- 字体：等宽字体用于数字/Token 金额，贴合「余额/日志」的技术感。
- 动效：克制（出牌轻位移、炸弹抖动、结算计数动画），不做花哨粒子。
- 交互：按钮和桌别卡片提供清晰的 hover、focus、selected、disabled 状态；支持减少动效设置。
- **品牌素材**：默认头像与牌背都基于 DeepSeek 品牌图（蓝 `deepseek-blue.svg` / 黑 `deepseek-black.svg`），同一元素贯穿「玩家形象 + 牌桌」，形成辨识度。
- 细节设计规范见 [assets/README.md](../assets/README.md)。

## 2. 核心玩法：3 人标准斗地主

### 2.1 对局流程
```
开始 → 洗牌发牌(54张, 17×3+3底牌) → 叫地主/抢地主 → 确认地主+底牌 → 出牌循环 → 一方先出完 → 结算 → 返回大厅
```

### 2.2 叫地主与抢地主
- 随机起始叫牌者（上局赢家可优先，首局随机）。
- 轮流「叫地主/不叫」；叫了之后可被「抢地主」加倍（最多 2 轮抢）。
- 若三家都不叫 → 重新发牌（不重复扣费，但算一次「洗牌重开」埋点）。
- 无人叫时的替代方案（可选）：由系统随机指定地主。

### 2.3 牌型（标准规则）
| 牌型 | 示例 | 说明 |
|---|---|---|
| 单张 | 3 | 单牌 |
| 对子 | 33 | 两张同点数 |
| 三张 | 333 | 三张同点数 |
| 三带一 | 3334 | 三张 + 任意单 |
| 三带二 | 33344 | 三张 + 一对 |
| 顺子 | 34567 | ≥5 张连续单牌（不含 2 和王） |
| 连对 | 334455 | ≥3 组连续对子 |
| 飞机 | 333444 | ≥2 组连续三张 |
| 飞机带单/带对 | 33344456 / 3334445566 | 飞机带翅膀 |
| 四带二 | 333345 / 33334455 | 四张带两单或两对（不是炸弹） |
| 炸弹 | 3333 | 四张同点数，可炸任何非炸弹 |
| 王炸 | 大小王 | 最大，可炸一切 |

- **大小**：3<4<...<A<2<小王<大王。炸弹 > 一切普通牌型；同牌型比最大点；王炸最大。
- **禁止**：顺子含 2 或王；飞机翅膀规则按通用线上规则实现（允许带对）。
- **过**：本轮不出；**跟牌**必须大过上家同类型（炸弹/王炸例外可改变类型）。

### 2.4 结算与倍数
- 基础分 = 桌别底注（见 §6）。
- 倍数叠加：炸弹 ×2（含王炸）；叫地主 +抢地主 次数 ×2（最多到「明牌加倍」可配置）。
- **春天**：地主首出且农民一张未出 → 结算 ×2；**反春**：农民先出完且地主未出牌 → ×2。
- 结算公式（每局）：
  - 地主胜：每农民付 `底注 × 倍数` 给地主。
  - 农民胜：地主付 `底注 × 倍数` 给两个农民（各半）。
  - 平台抽水：从**赢家所得**中抽取 `rake%`（默认 5%），输家支付额不变。
  - 示例：底注 100，倍数 8（2 炸 + 春天），地主赢 → 每农民付 800，地主得 1600×0.95 = 1520，抽水 80。

## 3. 局外系统

### 3.1 信息架构
```
启动插件
└─ 大厅（Lobby）
   ├─ 我的信息：昵称/头像/段位/余额
   ├─ 每日签到（200k，今日未领时高亮）
   ├─ 桌别选择（新手桌/进阶桌/高倍桌）→ 匹配队列
   ├─ 好友房（Phase 2）
   ├─ 我的对局（战绩）
   ├─ 流水
   └─ 设置（昵称/默认头像/音效/退出）
对局中：牌桌 → 结算页 → 返回大厅
```

### 3.2 匹配（Phase 1）
- 用户选桌别（底注档位）→ 进队列，显示「等待中… 已匹配 x/3」。
- 满 3 人自动开局；等待 > 90s 可退出；退出不扣费。
- 桌别门槛：余额需 ≥ 底注 × N（如 20 倍）才能进，防止秒破产。
- 匹配不按段位分（阶段一用户量少），只按桌别。

### 3.3 大厅状态
- 余额与段位实时刷新（服务端返回）。
- 签到：`/api/daily` 领取，幂等（同日重复请求返回已领取）。

## 4. 段位体系

### 4.1 段位定义（按 Token 总余额）
| 段位 | 名称 | 余额区间（Token） | 大约到账时间（仅签到） | 文案梗 |
|---|---|---|---|---|
| 1 | 小难梁 | 0 – 49.9 万 | 0–2 天 | 「新手，牌都还认不全」 |
| 2 | 牢梁 | 50 万 – 199.9 万 | ~3–10 天 | 「坐牢般打工攒 token」 |
| 3 | 梁子 | 200 万 – 999.9 万 | ~2–5 周 | 「量子纠缠般算牌」 |
| 4 | 梁圣 | 1000 万 – 4999.9 万 | ~2–7 个月 | 「靠赢牌登圣」 |
| 5 | 梁神 | 5000 万 – 1.999 亿 | ~1 年+ | 「凡人已不可及」 |
| 6 | 梁祖 | ≥ 2 亿 | 多年 / 赢牌才有 | 「开山立派」 |

> 阈值写在 `shared/config.ts`（可配置），上线后按数据调优。

### 4.2 段位规则
- 段位 = f(当前余额)。余额达标即升段，实时生效。
- **历史最高段位保底**：输钱不降段（记录 `peak_rank`），避免挫败。
- 升级：全屏横幅 + 动效 + 可复制分享文案。
- 段位仅展示与荣耀用途，不参与匹配/不设排位分（保持轻量）。

## 5. UI/UX 与流程

### 5.1 入口（贴合 DSH）
- 插件注册一个常驻入口（例如 DSH Web 界面中的「斗地主」面板入口 + 顶部菜单项）。
- **长任务提示**：DSH 在跑长任务时（如 LLM 流式输出/后台 job 运行中），可弹出轻提示「等待中，来一把？」——不打断，用户点开即进入大厅。此联动在 M1 spike 验证可接入点。

### 5.2 牌桌布局（桌面）
```
  ┌────────────────────────────┐
  │ [对手B]  头像 昵称 段位 余额 │   ← 对家
  │         (手牌背面 已出x张)   │
  │  [对手A]     底牌/地主标记    │   [对手C]
  │  (侧面)      桌面已出牌区      │
  │          [我的 17 张手牌]     │   ← 底部扇形
  │   [出牌] [提示] [过] [认输]    │
  └────────────────────────────┘
```
- 手牌拖拽/点击选择，选中高亮，自动提示合法牌。
- 出牌区显示「上一手谁出的、什么牌」。
- 倒计时条（每手 20s，剩 5s 变红）。
- Token 与倍数实时显示；炸弹/春天触发时牌桌抖动+计数。

### 5.3 结算页
- 三方结果、倍数明细、Token 变化（+/- 与抽水）、段位变化。
- 「再来一局 / 返回大厅 / 分享战报」。

### 5.4 文案风格（示例）
| 场景 | 文案 |
|---|---|
| 签到 | 「今日 200k 已到账，别再说 DSH 不给你发工资了」 |
| 输光破产 | 「余额见底，救济金已打款——打工人的相互救赎」 |
| 升段 | 「恭喜晋升【梁子】，量子开始纠缠了」 |
| 等待匹配 | 「3 缺 2……3 缺 1……到齐开打」 |
| Agent 出牌（Phase 2） | 「DSH：我分析了 12 种出法，这手稳赢」 |

### 5.5 自定义头像（**暂缓**）
- 用户决定暂缓：启用 R2 需绑定支付方式，第一阶段只用默认头像（DeepSeek 蓝/黑）。
- 设计保留（未来做时参考）：
  - 设置页「上传自定义头像」，与默认头像并列可选。
  - 处理流程：客户端选图 → canvas 裁方 → 转 **WebP**（q0.8，256×256、≤128KB）→ 上传 → 服务端校验后存 R2 → 返回地址。
  - 失败提示：非图片/超限/脚本注入 → 明确报错且不产生脏数据。
  - 上传成功埋点 `avatar_upload`（见 docs/数据埋点.md §5）。

## 6. 经济系统（Token）

### 6.1 发行
- **每日签到**：200k/天（唯一稳定发行源，Phase 1）。
- **救济金**：破产后每日一次 100k（保体验下限）。

### 6.2 流通与消耗
- **底注**（核心消耗）：对局入场与结算。
  - 新手桌：底注 10k
  - 进阶桌：底注 50k
  - 高倍桌：底注 200k（余额门槛 4M，即梁子以上）
- **平台抽水 rake**：赢家所得 5% 回收 → 抵消每日增发的通胀（见 6.4）。
- 无购买、无充值、无提现。

### 6.3 单局期望
- 每局三人合计净变化：0（输家支付 = 赢家所得 + 抽水）。系统每局回收 `赢家所得 × 5%`。
- 为维持通胀平衡，需要「日回收 ≥ 日发行」：
  - 日发行 = 200k × DAU + 救济金。
  - 日回收 = Σ(赢家所得 × 5%)。粗略估算：每人每天平均玩 ~10 局、平均下注流水 ~3 倍底注，需靠数值/抽水率调优。

### 6.4 通胀控制
- 抽水率默认 5%，可配置；若通胀超阈值（如均价对局回收不足），可：
  - 上调 rake 至 8–10%；
  - 高倍桌提高底注门槛；
  - 引入「段位入场券」（高段位进入高倍桌需小额手续费，Phase 2 评估）。
- 上线后按埋点数据（日发行 vs 日回收、流通总量、均价对局流水）持续调优，见 docs/数据埋点.md §6 指标。

### 6.5 防作弊 / 防刷
- 余额、领取、结算全部服务端权威（见架构设计 §6）。
- 每日领取幂等 + 限流 + 设备指纹关联；异常模式（如瞬时高额流水）标记告警。

## 7. DSH Agent 玩法（第二阶段）

### 7.1 三种模式
| 模式 | 构成 | 说明 |
|---|---|---|
| 人机混桌 | 玩家 + 2 Agent | 空位由 DSH Agent 接管，最快凑桌 |
| 观战对局 | 自己的 DSH vs 别人的 DSH | 全 AI 自动推进，玩家观战（可娱乐下注） |
| 好友混桌 | 2 玩家 + 1 Agent | 拉一个朋友，缺的位子让 Agent 顶上 |

### 7.2 Agent 行为规范
- 决策：轮到时，房主/托管方调用 DSH headless 会话：「你是斗地主玩家，手牌…上家…请出牌，只输出牌面」。
- 超时兜底：15s 未回 → 规则引擎出「最小合法牌」。
- 决策日志：把 Agent 的一句思考摘要随出牌展示（DSH 风格）。
- Agent 不追求必胜，只追求「看起来会打」+ 偶尔戏精（输出梗），保持娱乐性。

### 7.3 谁的 DSH 在打？
- 「自己的 DSH」：指用户本机的 DSH harness（localhost:3080），通过本机 bridge 调用 headless 会话。
- 「别人的 DSH」：对方的 DSH 以受控客户端身份连进同一房间，由对方插件代为决策。
- 房间协议不区分人类/Agent 座位——只区分「决策来源」，架构天然支持（详见架构设计 §8）。

## 9. 数值调优计划

- 上线后（M2）接入埋点，收集：对局数、平均倍数、人均局数、抽水回收 vs 发行、段位分布、停留时长。
- 定期（每 2 周）按数据调整：底注、rake、签到额、段位阈值。
- 目标：让 80% 玩家在「打 5–10 局后」余额仍能维持（不会一把输光劝退），同时段位成长节奏约 2–4 周升一级（中位用户）。

## 10. 开放问题

1. 3 人凑齐难 → 是否 Phase 1 末期就引入「简单机器人」（非 DSH Agent）垫桌？
2. 「等待提示」的触发时机（长任务判定标准）与不打扰的交互形态。
3. 段位是否参与匹配（用户量上来后）？
4. 是否要做「明牌加倍/加倍选项」等深度规则（先不加，保持简单）。
5. 牌面美术：写实扑克 or 工程师梗风格（如 K=「KPI」、Q=「Queue」）？→ 默认先写实扑克，梗作为彩蛋皮肤（Phase 2）。
