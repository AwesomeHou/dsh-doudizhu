## M1 · 本地最小闭环（预估 1–2 周）

**目标**：不依赖云后端，在 DSH 里能打开牌桌，打完一局完整斗地主（人 vs 简单机器人×2）。

| 任务 | 说明 | 验收 |
|---|---|---|
| 插件骨架 | 根 package.json / cordis.patch.yml / 客户端入口，注册一个「斗地主」入口面板 | 在 DSH GUI 中可见入口并可打开空大厅 |
| 规则引擎 | deck/valid/compare/scoring + 完整单测 | 单测覆盖全部牌型与结算，账目守恒 |
| 牌桌渲染 | 发牌、选牌、出牌/过/提示 UI | 可本地完成一次完整对局 |
| 简单机器人 | 规则引擎兜底出牌（先过，后接最小合法牌） | 机器人能打完一局 |
| 本地状态 | 余额/签到在 localStorage 模拟（M1 仅演示） | 签到与余额展示可用 |
| spike：slots 挂载 | 确认 DSH `dsh-client-ui-slots` 具体挂载点与 API | 架构 ADR-007 定稿 |

**M1 验收**：`dsh plugin --profile web add <本地路径>` 后可打开大厅 → 开局 → 打完整局 → 结算展示；引擎单测全绿。

## M2 · PVP 上线（第一阶段，预估 2–3 周）

**目标**：真实 3 人 PVP + 完整经济/段位 + 埋点。

| 任务 | 说明 |
|---|---|
| Cloudflare 后端 | Workers API + Room DO + D1 schema + 迁移 |
| 匿名身份 | UID 生成、token 签发、资料 API |
| 匹配 | 桌别队列 → 满 3 人开局 |
| WS 实时对局 | state/patch/turn/settle；断线重连与托管 |
| 经济 | 签到 200k、底注、结算、抽水、流水、救济金 |
| 段位 | 阈值判定、peak 保底、升级反馈 |
| 自定义头像 | 客户端转 WebP + 压缩 → 上传 → 服务端校验 → R2 存储（见架构设计 §3.5） |
| 埋点 | ingest + 事件字典 + Admin 报表（见数据埋点.md） |
| 风控 | 幂等领取、限流、异常告警 |

**M2 验收**：两台设备（两个 DSH）可匹配同一局完整打完并正确结算；余额/段位服务端生效；日活/对局数/经济指标可从 Admin 查询。

---

## M3 · DSH Agent（第二阶段，预估 2–3 周）

**目标**：DSH 成为牌手。

| 任务 | 说明 |
|---|---|
| Agent 桥接 | 本机 headless 决策调用 + 提示词模板 + 超时兜底 |
| 人机混桌 | 空位由 Agent 接管（自己的/别人的 DSH） |
| 双 AI 对局 | 全 AI 房间 + 观战渲染 |
| Agent 决策日志 | 每手思考摘要展示 |
| 恢复码 | UID 找回，防清浏览器丢号 |

**M3 验收**：玩家可与「自己的 DSH」打完一局；可开「自己的 DSH vs 朋友的 DSH」观战局；Agent 超时不卡局。

## 里程碑节奏建议

- M1、M2 各自独立可交付；M1 结束即可让用户本地体验，M2 结束可小范围内测。
- 每个里程碑结束做一次「数值/体验走查 + 埋点数据核对」，再进入下一阶段。
